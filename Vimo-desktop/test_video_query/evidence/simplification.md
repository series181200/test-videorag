# VQ 单样例调整记录

## 最新约定

用户要求重点检查功能和逻辑，每个业务用例只选一个代表样例。本次从 22 个检查精简为 4 条：VQ-001、002 各一个 pytest 样例；VQ-003、004 各一个 Vitest 样例。

- VQ-001 选三个空格的问题，保留真实接口对任务调度的拦截检查。
- VQ-002 选不存在的会话，保留真实接口和管理器，验证不会意外创建会话/进程。
- VQ-003 选超时反馈后重新提问，验证真实 useChat 的等待状态和消息恢复。
- VQ-004 选先 A 后 B，验证真实 useChat 的重复提交拦截及答案顺序。

接口允许合理的 4xx 错误，不强制固定错误码或文案。与业务无关的状态消息不参与对话顺序比较；问题和答案本身的对应关系仍必须正确。

移出的 Python 恢复/并发检查先前被状态写入问题阻断，该问题没有修复。VQ-003、004 现在只代表交互逻辑通过，不表示后端进程释放或并发保护通过。原始历史报告保留，业务代码没有修改。

## 实际结果

4 条均正常收集：2 通过、2 失败；无基础设施错误、无跳过。

| ID | 结果 | 说明 |
| --- | --- | --- |
| TC-VQ-001 | FAIL | 全空格问题仍被接口下发给调度方法 |
| TC-VQ-002 | FAIL | 不存在的会话仍被创建目录并启动了进程替身 |
| TC-VQ-003 | PASS | 超时后停止等待，重试收到新答案，保留历史消息 |
| TC-VQ-004 | PASS | A 回答前不下发 B，随后两次答案正确对应 |

VQ-001 对调度方法使用依赖替身，准确结论为入口未拦截；VQ-002 使用真实管理器，但没有启动操作系统真实进程。4 条检查不代表整个部署链路都已验证。
