# VQ 实施与验证记录

## 任务与方法

用户要求根据 `test_video_query/README.md` 实现另外一部分测试代码，并保证质量。本次遵守 TypeScript 用 Vitest、Python 用 pytest 的约定，保留 TC-VQ-001 至 TC-VQ-004 的业务划分。没有修改业务源码，没有修改 SC 测试，没有调用真实模型或付费接口。

此文档是 AI 实施过程摘要，不是原始对话的逐字导出。用户提供的清单、README 和当前任务对话是本次生成依据。尚未完成团队人工验收，不将 AI 自查写成人工审核结论。

## 测试设计与质量检查

- 12 个 pytest 检查与 10 个 Vitest 检查分进程运行，防止 Python 模块替身污染其他套件。
- Python 显式加载业务文件并核对 `__file__`，未导入测试目录下的 API 副本。
- 路由参数检查与真实管理器检查分别声明隔离边界，保留正常输入对照，避免“总是拒绝”也能通过。
- 真实状态写入失败时记录前置阻断，没有通过 Mock 写入函数制造假通过。
- React 测试调用真实 `useChat` 和消息处理工具，检查消息内容、等待状态及终态后的轮询次数；依赖替身只提供上下文、索引元数据与 IPC 返回。
- 两种框架的结果均保留原始报告。每个业务 ID 必须收集齐其预期数量的检查，并全部通过，才能标记通过。
- 模拟 worker 主动抛出超时的代码已实现，但当前后端被启动前的文件写入失败阻断；未验证模型永不返回的硬超时终止。

## 调试与修正

1. 首轮发现 React Router 从应用依赖目录加载 React，而 Testing Library 使用测试依赖目录的 React，导致 useRef/Invalid Hook Call。统一从一个依赖目录解析 React、React DOM、Router 和 Testing Library 后解决。这是测试环境错误，不能计入产品缺陷。
2. 替换了 Vitest 2.1.9 不支持的 `toHaveBeenCalledExactlyOnceWith`，改为次数和参数两个独立断言，未改变预期。
3. 分离 pytest 公共断言到 `python_support.py`，避免测试模块直接依赖 conftest 的辅助函数导入。
4. 最终所有检查均被收集；没有 skip/xfail。前两轮报告仅供调试追踪，业务结论以最终有效报告为准。

## 结果解释

- 空字符串和其他空白组合经过真实路由后仍调用了调度方法。由于这组路由检查替换了调度方法，准确结论是“未在入口拒绝空白问题”，不能仅凭它宣称真实进程一定已创建。
- 不存在的会话请求在真实管理器中创建了目录和查询进程；未索引、正在索引的请求返回了不符合约定的结果。已存在状态文件的更新会遇到 WinError 183，应将状态写入问题与查询准入问题分开分析。
- 索引已完成的正常查询对照同样在写入状态时失败。恢复与并发用例的第一次查询因此无法启动，当前不能确认模型超时清理或第二个查询的后端保护是否正确。
- 前端已验证 processing → error → 重试 → completed，以及 A 处理中拒绝 B、A 完成后再提交 B、两次答案顺序保持正确。这里是 hook 与消息逻辑的隔离验证，不是完整桌面部署测试。
- 未修复业务代码，未产生修复后回归结论。后续先解决真实状态写入问题，再执行相同用例才能继续验证后端恢复和并发。
