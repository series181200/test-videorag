# SC 单样例调整记录

## 最新约定

用户要求不必过于严格，重点检查功能和逻辑漏洞，每个业务用例只选一个样例。本次把 14 个自动化检查精简为 5 条，各业务 ID 恰好一条。

SC-001 选部署文件缺失，SC-002 选短暂不可达后的自动恢复，SC-003 选损坏 JSON 修复，SC-004 选无效密钥，SC-005 选模型文件缺失。移出固定 3 轮/60 秒要求、多个字段组合、认证成功/超时对照、存储写权限等扩展检查。错误文案和内部调用精确次数不作为通用验收要求。

长期不可达后的有限退出，以及目录不可写等旧问题仍未修复。本轮通过仅证明所选样例；不覆盖原清单中该 ID 的所有子场景。业务源码没有修改，原始历史报告没有删除。

## 实际结果

5 条均正常收集：4 通过、1 失败；无收集错误、无跳过。

| ID | 结果 | 说明 |
| --- | --- | --- |
| TC-SC-001 | PASS | 缺少后端文件时无法启动，未创建进程 |
| TC-SC-002 | PASS | 后端暂时不可达后恢复，可以自动连接 |
| TC-SC-003 | PASS | 损坏配置阻止初始化，修复后可以重新初始化 |
| TC-SC-004 | FAIL | sk- 开头的假密钥仍被直接返回验证成功 |
| TC-SC-005 | PASS | 模型缺失时失败，模型恢复后初始化成功 |

认证测试仅配置了服务端拒绝的替身；当前 handler 没有执行认证请求，因此不能说真实认证服务器已经拒绝过该密钥。
